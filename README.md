# task_to_robot_toy

2D (SE(2)) prototype of task-informed kinematic synthesis: from a task
(workspace, target poses with heading tolerances, circular obstacles) derive
lower bounds and a reduced design space, then fit the smallest planar serial
R/P chain that reaches every target without collision.

The repository holds two pipelines:

- **Geodesic, reach-only pipeline** (current): `src/*.py`, run by
  `src/run_geodesic_pipeline.py`.
- **Legacy bracket-based pipeline**: `src/legacy/`, run by
  `src/run_pipeline.py`. Kept unchanged so the earlier preliminary results
  stay reproducible.

## Geodesic pipeline

| File | Stage |
|---|---|
| `src/problem.py` | Task definition (`ToyProblem`, presets), fixed physical parameters (base angle, probe, link radius, margin, grid), exact segment clearance, SE(2) and twist-metric helpers |
| `src/targets.py` | Stage 1: target pose sets. Heading bands are sampled and pruned where the probe would hit an inflated obstacle; each target fixes c_k = 2 (interval) or 3 (exact heading) coordinates |
| `src/geodesic_field.py` | Stage 2: per-target geodesic distance (fast marching), field = -grad d, dead-band orientation rule, RK4 reach paths, and route ties |
| `src/bounds.py` | Stage 3: counting bound (total joints), minimum-link bound (revolute joints after the first), length bound |
| `src/classes.py` | Stage 4a: motion-class coset tests, admissible joint combinations, rho |
| `src/priors.py` | Stage 4b: segment paths (constrained Douglas–Peucker), bend clusters, approach cones, starting designs |
| `src/stage5_6.py` | Stage 5: direct fit of every admissible combination to all targets at once, smallest joint count first, early stop, minimality evidence. Stage 6: validation |
| `src/run_geodesic_pipeline.py` | Runs Stages 1–6 and writes figures and JSON reports |
| `src/experiments/ground_truth.py` | E4: tasks generated by known mechanisms |
| `src/experiments/ablations.py` | E5: sensitivity to grid, inflation, tolerance, probe, characteristic length, orientation rule |

Kinematic conventions: the base angle is fixed; links are straight with no
fixed bends; a prismatic joint is a telescoping segment (housing plus
extension) along the current link, and a leading prismatic joint has a fitted
slide direction; a fixed probe follows the last joint, and the end-effector is
its tip.

Terminology: *reach path* is the field streamline from the base to a target,
and *segment path* is its straight-segment simplification. Both are
placeholder names.

## Setup

Tested with Python 3.12.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

`scikit-fmm` provides the fast-marching distance. If it does not install,
`geodesic_field.py` falls back to `skimage.graph.MCP_Geometric` (install
`scikit-image`), which is less accurate on diagonals.

## Run

```bash
cd src
../.venv/bin/python run_geodesic_pipeline.py --problem one_obstacle --seeds 10
../.venv/bin/python run_geodesic_pipeline.py --problem multi_target_wide --seeds 10 --starts random
../.venv/bin/python run_geodesic_pipeline.py --problem one_obstacle --seeds 10 --field potential

../.venv/bin/python experiments/ground_truth.py --trials 4 --search
../.venv/bin/python experiments/ablations.py --problem one_obstacle --seeds 3

../.venv/bin/python run_pipeline.py                          # legacy pipeline
```

Problems: `one_obstacle`, `multi_target_wide`, `multi_target_exact`,
`parallel_branches`, `two_obstacles`. Start modes: `priors` (default),
`random`, `legacy_icr`. Each run of the geodesic pipeline writes to
`images/geodesic/<run>/` and `reports/geodesic/<run>/`, where `<run>` is the
problem name, suffixed with the start mode and field when they are not the
defaults. `06_starts_comparison.png` compares every start mode that already
has a report for the same problem and field, so run the non-default modes
first. All outputs are generated, so they are not tracked.

## Tests

```bash
.venv/bin/python -m pytest tests/
```

`tests/test_geodesic_pipeline.py` covers the geodesic pipeline;
`tests/test_stage3_bracket.py` and `tests/test_stage4_6_fixes.py` cover the
legacy pipeline in `src/legacy/`.
